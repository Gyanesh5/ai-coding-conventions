# 测试规范

---

## 测试分层

| 层级 | 目标 | 速度 | 依赖 |
|------|------|------|------|
| 单元测试 | 单个函数/类的逻辑正确性 | 快（<1s） | 无外部依赖（mock） |
| 集成测试 | 模块间协作正确性 | 中（秒级） | mock 的外部服务 |
| E2E 测试 | 完整业务流程 | 慢（分钟级） | 真实/仿真环境 |

单元测试禁止依赖外部服务。

---

## 测试设计：少而全

覆盖全的本质是**划分输入空间**，不是堆用例。测试数量约束在公共接口（seams）上，不随内部函数数量增长——内部函数靠接口测试间接覆盖，重构内部实现不动测试。

- **参数化代替复制**：一个测试函数 + 等价类/边界值表 ≈ 十几个独立用例，新增边界只加一行数据
- **组合爆炸治理**：多参数不做全组合（n 维 = 2^n），每维按等价类取代表值；发现维度交互缺陷再补组合
- **属性测试**：纯函数且有不变量的场景（坐标变换可逆、round-trip、对称性）用一条 property（Hypothesis）代替一批点断言，覆盖密度最高、数量最少

## AAA 模式

Arrange → Act → Assert。

---

## 合成数据

使用合成数据，不依赖真实文件/硬件。

---

## 边界测试

覆盖零值、空容器、最大值、负值。

---

## 测试隔离

每个测试独立运行，不依赖执行顺序。

---

## 测试错误路径

不只测试正常路径，必须覆盖错误场景。

---

## 断言强度

期望值必须来自**独立真值源**（已知算例、手工推演、不变量），禁止用与实现相同的逻辑重算期望值——那种测试天然通过，是假测试，也是 agent 生成测试的高发缺陷。

- 优先不变量断言：round-trip（编码→解码还原）、可逆性、守恒性、对称性——对参数扰动不敏感，实现换算法测试不失效
- 新测试合入前做一次变异验证：破坏实现（删一行/反转条件）确认测试变红，再还原——不会红的测试没有存在的意义
- agent 生成测试的系统性盲区，人工补这五类：`None`/null、负数、空容器、异常路径、时区与时间

---

## Mock 原则

**只 mock 外部边界（HTTP、数据库、硬件），不 mock 内部逻辑。**

mock 内部模块会使测试与实现细节耦合——实现重构时测试失败，但行为并没变。

```python
# ✅ mock 外部边界
@patch("src.camera.cv2.VideoCapture")
def test_capture(mock_vc):
    ...

# ❌ mock 内部逻辑 —— 测试无意义
@patch("src.service.process_data")
def test_capture(mock_process):
    ...
```

---

## 禁止骗绿

禁止为了让测试变绿而弱化断言、跳过用例、特判测试输入。测试变红说明实现或测试有一方错了——修根因，不是修信号。

---

## 覆盖率 ≥ 80%

针对新增/改动代码，不追溯历史代码。覆盖率不能替代测试质量——高覆盖+弱断言=假覆盖。

---

## 测试退役

测试套件只进不出是慢性病。清理按四分类，**举证责任在删除方，默认保留**：

| 类别 | 判定 | 处置 |
|---|---|---|
| 过时 | 测的行为/模块已不存在 | 删（唯一直接删的类，先向行为 owner 确认） |
| 冗余 | 覆盖同代码且幸存测试杀死相同变异 | 隔离 → 变异确认 → 合并/删 |
| 低值 | 从未失败且无有效断言 | 隔离 → 人工 review（低值≠零值） |
| 保留 | 独有覆盖/有抓错历史/守高危路径 | 保，无视重叠 |

删除门槛（四条全成立才删；缺输入按不删算）：窗口期内无抓错记录；逐测试证明冗余（合并覆盖率报告不算数）；无 `@critical` 类保护标签；未标待重写——烂测试是修，不是删。

- **skip 30 天规则**：skip 超 30 天无人处理，要么修好启用要么删，不允许永久墓碑；环境性 skip（CUDA/显示设备）不在此列
- **软删除**：先隔离（skip 带审计原因）→ 观察一个迭代 → 小批硬删；独立 commit，逐条记录理由与被谁取代（防 agent 重建同款低值测试）
- **agent 只提案不执行**：清理候选（skip 年龄/覆盖重叠/变异 survivor）可由 agent 扫描产出，删除必须人签核

---

## 测试节奏三档

Agent 红绿循环内**禁止跑全量测试**——每次改动只跑相关部分，全量留给提交/合并前：

| 时机 | 跑什么 | 预算 |
|---|---|---|
| 内循环（每轮改动验证） | 改动相关测试文件 `-x`，或 `--lf -x`（上轮失败优先） | 秒级 |
| 提交前 | 快集：`-m "not slow" -n auto` | < 30s |
| 合并前 / CI | 全量：`-n auto` | 不设限 |

- 单测 ≥ 1.5s 的（真实求解、超时退避等待类）标 `@pytest.mark.slow`，并在 pyproject 的 `[tool.pytest.ini_options]` 注册 marker（`--strict-markers` 项目必须注册）
- 并行用 pytest-xdist（`-n auto`）；共享硬件或固定端口的测试隔离到串行
- 项目 AGENTS.md 的「构建和测试」段按此三档填写**本项目**的具体命令，禁止只写一条全量命令

---

## 性能基线

单元测试全量 < 10 秒，单测试 < 50ms。快集超预算先治理最慢测试（`pytest --durations=20` 定位长尾），不是加并行度。重初始化（模型加载、大图、标定数据）放 `session` 级 fixture 共享，不进单测。

---

## 硬件测试

硬件相关测试单独放 `tests/hardware/`，不在 CI 中运行。
